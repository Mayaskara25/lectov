LECTOV — TEACHER-FACING IMPROVEMENTS & COST NOTES
====================================================

## CONTROL IMPROVEMENTS (ordered by priority)

A — Plan review + edit before rendering [HIGHEST VALUE]
  - New endpoint: POST /plan
      Returns planner JSON (sections, formulas, timings, colors)
      without running the writer yet
  - Teacher edits the JSON (fix notation, reorder sections,
      change duration, add/remove sections)
  - New endpoint: POST /generate-from-plan
      Takes the edited plan JSON, skips the planner,
      goes straight to the writer
  - Benefit: catches formula notation issues before any code runs,
      eliminates a whole class of repair-loop failures

B — Structured input form instead of raw notes
  - Teacher fills a short form instead of uploading raw .txt:
      Topic, Target audience, Duration, Key formulas,
      Must-cover points, Style preference
  - Formula extraction (most error-prone part) done by human not AI
  - This replaces or tightens the planner brief significantly

C — Visual style presets
  - Single style= parameter that changes writer prompt variant:
      formula_walkthrough  → formula → step-by-step derivation
      concept_overview     → title card → bullet definitions → summary
      worked_example       → problem statement → steps → answer box
      side_by_side         → theorem left column, diagram right column
  - No code changes for the teacher — just a field in the upload form

D — Feedback refinement on existing video
  - New endpoint: POST /refine/<job_id>
  - Teacher provides text note after watching:
      "make section 2 slower"
      "product rule formula is wrong, should be (fg)' = f'g + fg'"
      "add a visual for the limit definition"
  - Loads existing scene file, runs targeted repair with feedback injected
  - Re-renders only what changed

E — Personal style config (one-time teacher setup)
  - Teacher defines once, injected into every planner + writer prompt:
      notation: "prime notation f'(x) not Leibniz Df(x)"
      color_scheme: "dark background, blue theorems, green examples"
      always_include: "start every video with a motivating question"
      never_include: "no Greek letters without defining them first"
  - AI always writes in the teacher's voice without being reminded

F — Section-level regeneration
  - If 4 of 5 sections are good, regenerate only the bad section
  - Requires splitting scene into independent construct() blocks
  - Eliminates full re-render for small fixes
  - More complex to implement — do after A-D are done


## COST ESTIMATE (5-6 videos/day on OpenRouter credits)

Token breakdown per video (typical, ~1 repair cycle):
  Planner:       ~1,000 input  +   ~500 output
  Writer:        ~1,500 input  + ~1,500 output
  Repair (avg):  ~3,000 input  + ~1,500 output
  Total:         ~5,500 input  + ~3,500 output = ~9,000 tokens/video

At 5-6 videos/day: ~50,000 tokens/day

Model combo                              | Cost/video | Monthly (30 days)
-----------------------------------------|------------|------------------
DeepSeek V3 writer + free planner        | ~$0.005    | ~$0.75
DeepSeek V3 writer + paid planner        | ~$0.01     | ~$1.50
GPT-4o-mini writer + planner             | ~$0.02     | ~$3.00
GPT-4o writer + GPT-4o-mini planner      | ~$0.08     | ~$12.00

Recommendation:
  - $10 OpenRouter credit with DeepSeek V3 lasts 6-12 months at 5 vids/day
  - GPT-4o-mini for better quality: $10 credit lasts 3-4 months
  - Free tier costs nothing but has 503/429 reliability issues —
    for daily classroom use $5-10/month on paid models is worth it

Key insight: the repair loop is the dominant cost driver, not the planner.
A stronger (more expensive) writer that avoids repairs often costs LESS
in total than a cheap writer that triggers 3 repair cycles.
